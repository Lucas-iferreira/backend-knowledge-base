# Design Patterns

## O que é?
Design Patterns (ou Padrões de Projeto) são soluções genéricas e reutilizáveis para problemas recorrentes no desenvolvimento de software.

Em vez de ser um código pronto ou uma biblioteca que você copia e cola, um design pattern é como um modelo ou gabarito conceitual de como resolver uma determinada situação. Ele descreve uma arquitetura de código testada e comprovada que pode ser adaptada para a sua linguagem ou contexto.

---

## Por que foi inventado?

- Evitar "reinventar a roda": Desenvolvedores no mundo todo passavam por problemas muito parecidos de arquitetura. Catalogar as melhores soluções poupa tempo e evita que cada equipe crie gambiarras do zero.
- Criar um vocabulário comum: Padrões servem como um "idioma técnico". Em vez de explicar toda a estrutura complexa de como os objetos vão conversar, um desenvolvedor pode apenas dizer "vamos usar o padrão X aqui", e toda a equipe entende a arquitetura imediatamente.
- Garantir a manutenibilidade e flexibilidade: Softwares tendem a crescer e mudar. Padrões de projeto aplicam os melhores princípios de orientação a objetos (como baixo acoplamento e alta coesão) para garantir que o código continue fácil de alterar, testar e expandir no futuro sem quebrar o sistema.

## Para que servem em resumo?
- Escrever código limpo: Garantem que o código siga boas práticas consagradas da indústria.
- Facilitar a comunicação: Aceleram discussões técnicas entre programadores.
- Tornar o software escalável: Ajudam a estruturar sistemas para que eles suportem mudanças de requisitos com o menor impacto possível.
